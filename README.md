# FlowTask — 本地项目管理平台

单文件、零依赖、本地优先的团队任务管理工具。整个前端是一个 HTML 文件，数据落在本机的 JSON 文件里，配合 Windows 自带的 PowerShell（或 Node.js）存储服务运行，拷走整个文件夹即可换机使用。

当前版本 **v2.1.1**（变更记录见 [CHANGELOG.md](CHANGELOG.md)，设计规范见 [DESIGN.md](DESIGN.md)）。

## 下载与两种用法

| 形态 | 拿什么 | 怎么用 |
|---|---|---|
| **桌面版（推荐）** | [Releases](https://github.com/sctale/FlowTask/releases) 里的 `FlowTask_x.y.z_x64-setup.exe`（安装）或 `FlowTask-Portable_x.y.z.zip`（免安装） | 双击即用：内嵌服务端与运行时，零依赖，数据在 exe 旁边；托盘常驻 |
| **网页版** | 源码页下载 `FlowTask_本地项目管理平台.html`（或整个源码包） | 双击 HTML 立即体验（数据暂存浏览器）；配合同目录 `启动 FlowTask.vbs` 获得按账户的本地文件存储 |

两个形态共用同一份服务端代码与同一套数据文件格式，可混用、可互相迁移。
产物均带 SHA256（见 Release 附件 `SHA256SUMS.txt`）。

> **给第一次拿到这个文件夹的同事**：看 [使用说明.md](使用说明.md)（新电脑怎么起、怎么改共享目录、
> 怎么开账号、个人项目与团队共享项目的区别）。下面这份 README 偏工程与实现。

> **数据按账户存放，全部是 .json 文件**——公司电脑会锁定被编辑过的 Office / txt / pdf，
> 本工具不产生任何这类文件。

## 功能一览

- **项目管理**：项目 / 任务（待办·进行中·已暂停·已完成 状态分组，即列表与看板列）/ 子任务 / 标签 / 关注人 / 重复任务（每天/每周/每月）
- **拖拽排序**：任务在列表内上下拖动可排序（同组换位、跨组改状态）；侧栏项目也可拖动调整顺序（顺序是个人偏好，只存本机，不改数据文件）
- **五种视图**：详情（项目播报/成员负载）、列表（拖拽排序）、看板（拖拽跨列）、日历（含子任务截止日期）、排期（甘特图）
- **我的任务**：按 已逾期 / 今天 / 稍后 / 无日期 分组，含指派给我的子任务
- **今天页**：「今天要处理」与「未来 7 天到期」同时纳入**子任务**（带「子任务」标记、缩进显示所属项目与父任务，点开即子任务详情；已完成的子任务不出现）；子任务行首有完成圆圈，点击直接完成/恢复
- **子任务排序**：任务抽屉里的子任务可上下拖动排序（有落点指示线，仅可写成员）
- **活动记录折叠**：任务与子任务的「活动记录」平时只显示**创建记录 + 最近 3 条**，点「显示全部 N 条动态」展开、可再收起；展开状态在本次会话内记住（发评论、改状态重绘后不会弹回折叠）
- **子任务详情**：与主任务能力一致——评论（发送/编辑/删除）、描述、状态/负责人/起止日期/优先级（可继承主任务）、标签、关注人、重复、活动记录、删除（6 秒可撤销）；唯一区别是不能再嵌套子任务
- **快速添加语法**：标题里可随手写 `@负责人`、`!高/!中/!低`、`#标签`、
  `今天/明天/周五/下周二/3天后/9月5日/2026-09-05`，识别结果实时回显并自动填入下方控件
- **筛选与批量**：状态/负责人/优先级/标签四维筛选，按「项目 × 视图」各自记住（刷新与切视图都不丢）；
  常用组合可**存为筛选视图**（团队共享、随备份走）；批量完成/指派/改期/删除均有反馈与撤销
- **任务复制**：抽屉里一键生成同项目同状态副本（剥离评论与活动记录），可撤销
- **移动任务**：把任务搬到其他项目——任务抽屉的「所属项目」显示当前项目，点击弹出**可搜索切换器**（输入即过滤、↑↓ 选择、Enter 确认），或多选后批量条「移到项目…」；
  子任务、评论、关注人与动态一起走，落位到目标项目同状态分组的末尾，可撤销；
  权限要求对源任务和目标项目都有写权限；跨个人库 ⇄ 共享库自动迁移
- **数据导出**：三个入口（项目页图标、我的任务、数据管理）都进同一个「导出」弹层，选**范围 → 内容 → 格式**，
  边选边预览行数与文件名。**表格 CSV** 给 Excel（带 UTF-8 BOM 中文不乱码、`=`/`+`/`@` 开头的标题自动加前导
  单引号防公式注入）；**Markdown 摘要** 按项目分组、可一键复制贴进钉钉/邮件；**JSON 备份** 仅用于导入还原。
  范围里的「当前筛选结果」与列表页共用同一套筛选逻辑，**看到什么就导出什么**；勾选「展开子任务」会自动带上
  「类型 / 父任务」两列，否则子任务行无法分辨归属。只包含你有权看到的项目；列全取消或行数超上限时会拒绝导出并说明原因
- **分享链接**：打开任务即写入深链，抽屉右上角「复制链接」发给同事可直接定位
- **通知**：指派、评论、邀请、项目播报等通知，支持全部标为已读
- **权限**：管理员 / 成员 / 访客（只读）三级；**项目可见性只认成员名单，管理员也不例外**
  （把人移出项目后他就不该再看到它）。管理员需要纵览全部项目时，点侧栏「项目」旁的 👁
  「显示全部项目」——只存本机偏好，不改任何数据
- **回收站**：任务/项目删除先进回收站，30 天内可恢复，删除操作带 6 秒"撤销"；清空按管理权分范围（成员清自己的，管理员清全部）
- **应用内帮助**：顶栏「?」或按 `?`，含快捷键 / 数据与备份 / 权限 / 分享链接四段说明
- **已暂停（On hold）**：第四种任务状态，表示"这件事暂时不推进，但没做完"。暂停的任务不进今天页
  「今天要处理 / 未来 7 天」、不计入侧栏未完成角标、**不再被催办逾期**（到期显示为日期而不是红色逾期），
  列表里单独收纳成一个可折叠的「已暂停」分组，看板上是独立一列；重复任务暂停后不会自动生成下一期
- **添加成员**：管理员在「成员管理 → 新建成员账户」创建，可选角色（成员/访客/管理员），角色会真正落盘
- **项目协作的真实门槛**：个人项目的数据存在**你自己的个人库文件**里，服务端只把它发给你本人——
  所以「把同事加进 memberIds」本身不会让对方看到任何东西。现在保存成员时若名单里出现同事，
  项目会**自动共享给团队**（连任务、通知、回收站条目一起搬进 `flowtask_shared.json`），
  并当场说明；侧栏用 🌐 团队共享 / 🔒 个人 / ⚠️ 个人项目却写着同事名单 三种标记让归属一眼可辨。
  归档项目不会被偷偷搬库，搬库仍需"创建人或管理员"权限
- **删除成员**：管理员可「停用」（随时可启用回来，推荐）或「删除」。删除不可逆，确认框会先说清楚
  三件事：他的个人库**改名留底**成 `deleted_flowtask_data_<uid>_<时间>.json`（不直接删文件）、
  名下未完成任务与项目不会消失（显示为「已注销用户」，需另行改派）、只是不想让他登录请用停用。
  删除会立刻作废他的登录会话，之后任何页面的旧快照都救不活这个账户（见「安全」段的 tombstone）
- **数据安全**：令牌鉴权 + 版本冲突可决策（副本可下载）+ 自动备份 + 损坏自动隔离（见下）
- **偏好设置**（个人设置页）：进入项目时默认打开哪个页面、打开应用时进哪里、任务行显示几个标签、新建任务的默认状态。偏好只存本机，不写进任务数据
- **可达性与适配**：纯键盘可完成"打开任务 → 改状态 → 关闭"；≤900px 侧栏改抽屉式，≤640px 栅格降单列
- 全局搜索（匹配任务/描述/子任务/子任务描述，`/` 聚焦、↑↓ 选择）、导入导出

## 快速开始

0. **拷贝到新电脑**：停服务 → 拷贝整个文件夹 → 双击 **`环境检查与部署.bat`**——
   自动检查运行环境（PowerShell/Node）、数据文件完整性、端口占用，然后交给启动器
   完成部署（启动服务 + 按新机路径重建快捷方式 + 打开浏览器），各账户首次登录一次即可。
1. **双击带 FlowTask 图标的 `FlowTask.lnk`**（首次运行 `启动 FlowTask.vbs` 会在本目录与桌面各生成一个）：
   自动探活 → 需要时静默启动存储服务 → 打开 <http://127.0.0.1:5178>。服务已在运行时不会重复启动，
   全程**不会闪命令行窗口**（脚本只做文件系统探测，不起 cmd 子进程）。
2. 也可以不启动服务，直接双击 `FlowTask_本地项目管理平台.html`：数据暂存浏览器缓存
   （顶栏提示"⚠ 仅浏览器缓存"，启动服务后点它即可把数据迁移到本地文件）。
3. 每次进入都需要登录；会话由服务端签发、**7 天有效**，期间重开浏览器免登录。
4. 停止服务：双击 `停止存储服务.bat`。

顶栏存储状态有四种：`保存中…` / `已保存 14:32:05` / `文件存储` / `仅浏览器缓存`（或 `保存失败 · 重连中`），点它可以重新检测。

演示账户（首次自动创建）：`admin / admin123`、`member / member123`、`guest / guest123`。
演示内容自带一个**团队共享项目**和一个**个人项目**——换 `member` 登录就能直观看到账户隔离效果：
共享项目双方都在，个人项目只有创建人看得到。

生产使用时请注册新账户（第一位自助注册者成为管理员）并修改或停用演示账户。

## 桌面版（FlowTask.exe，v2.1 起）

不想开浏览器？双击 **`FlowTask.exe`** 就是原生窗口应用（Tauri 壳 + 内嵌服务端，目标机器零依赖）：

- **免安装**：`desktop/src-tauri/target/release/FlowTask.exe` 拷到任意文件夹，双击即用，
  数据文件就生成在 exe 旁边——「拷走文件夹即搬家」与网页版完全一致；
- **托盘常驻**：点窗口 ✕ 只是隐藏（服务继续跑，局域网同事不受影响），托盘右键「退出」才关；
- **与网页版共存**：启动时先探测 5178——已有服务（vbs 起的或同事的）就直接复用，不重复起进程；
- **安装包**：`bundle/nsis/FlowTask_x.y.z_x64-setup.exe`（用户级安装，无需管理员）。

自己构建（需 Rust + VS Build Tools）：

```bash
cd desktop
npm install
powershell -File build_release.ps1   # 一键：sidecar→签名→主程序→安装包→dist/ 汇总
```

### 代码签名与杀软误报

- 构建链对 **sidecar / FlowTask.exe / 安装包** 三个产物统一做 Authenticode 签名
  （SHA256 + 时间戳）。这一步顺带治好了 360 等杀软的主要误报诱因——
  Node SEA 注入会破坏 node.exe 的原始签名，「残缺签名」比「无签名」更可疑。
- 本机用自签证书（`desktop/scripts/ensure-cert.ps1` 一次性生成，存
  `%USERPROFILE%\FlowTaskSign\`，**绝不入库**），本机信任链干净。
- **对外发布**：自签证书在别人的机器上不受信，建议购买 OV/EV 代码签名证书后
  仅替换证书指纹即可复用整条流水线；被误报时可向杀软厂商提交白名单复检（附 SHA256SUMS.txt）。
- 发布：`dist/<version>/` 即完整发布物（免安装 + 安装包 + sidecar + SHA256SUMS.txt），
  本地构建后直接上传，无需 CI。

桌面版跑的服务端就是仓库里这份 `flowtask_server.js`（esbuild 捆成单文件 Node SEA 注入），
不存在第二实现；壳只做窗口/托盘/进程管理（`desktop/src-tauri/src/main.rs`，约 200 行）。

## 术语表（全站统一用词，改文案前先看这里）

| 概念 | 界面用词 | 代码字段 | 说明 |
|------|----------|----------|------|
| 容器 | 项目 | `projects` | 不叫"空间/看板" |
| 归属 | 个人项目 / 团队共享项目 | `project.scope` = `personal` / `shared` | 决定这个项目的数据存在哪个物理文件；**把同事加进成员名单会自动共享给团队** |
| 工作项 | 任务 / 子任务 | `tasks` / `subtasks` | 看板的列也是任务，不叫"卡片" |
| 分组 | 状态（待办 / 进行中 / 已暂停 / 已完成） | `status` | 状态即列表与看板的列，无自定义分区；四种状态只有一处定义（`STATUS_DEF`） |
| 执行者 | 负责人 | `assigneeId` | 动作叫「指派给…」，空态叫「未指派」 |
| 项目建立者 | 项目创建人 | `projects.ownerId` | 与任务负责人区分，不混用"负责人" |
| 动态接收者 | 关注人 | `task.followers` | 只接收动态通知，**不代表有编辑权** |
| 优先级 | 高 / 中 / 低 | `priority` | 不写"高优先/高优先级" |
| 删除 | 删除任务（进回收站）/ 彻底删除（不可恢复） | `trash` | 两级词汇，不混用 |
| 冲突留底 | 冲突副本 | `flowtask_data_conflict_*.json` | 界面上不出现 "conflict" 字样 |
| 登录态 | 会话 | `flowtask_session_v2`（localStorage） | 服务端 HMAC 签发，7 天有效 |

状态色板与优先级色板统一由 `:root` 的 `--st-*` / `--prio-*` 令牌定义，
组件不得再写死 hex；任务状态的名称/类名/颜色单源于 `STATUS_DEF`。

## 账户与会话

- **登录时密码由服务端校验**：页面先向 `/api/auth-challenge` 取该用户的盐与算法，
  本地算出 PBKDF2 证明后换取会话——**页面拿到的账户表已脱敏，不含任何人的 salt/密码哈希**，
  只凭 uid 无法换取会话（v1.6 起）。
- **未登录只能读写账户表**：个人库与共享库一律要求携带有效会话，服务端返回 401；
  未登录时页面内存里不存在任何任务数据。
- **账户表写入按字段级守卫**：改角色、改他人密码都需要管理员会话或本人会话，缺的 `salt`/哈希
  由服务端用存量值补齐——一张脱敏的、过期的标签页再也顶不掉真实账户表。
- **整表回写既删不了人，也救不活人**：账户表读取是脱敏的，每台机器手里都可能是过期快照，
  所以「少一行」不再被当成删人（服务端把存量补回来；早先直接判 403 会把正常的建号一起打死），
  删人只能走 `POST /api/delete-user`——它才会留底个人库、作废会话、写 tombstone；
  已进 tombstone 的账户即使在请求里被带回来也会被丢掉，且 tombstone 只并集、不会被整表回写洗掉。
- **账户表写入失败绝不假装成功**：建号 / 改角色 / 停用都会等服务端确认，确认不了就把这一处改动回滚、
  把服务端给的原因原样显示出来（此前会先弹「已创建账户」再把失败咽进 console）。
- **账号只由管理员开通**（v1.9，默认）：表里已有活跃账户时，没有管理员会话就建不了号；
  登录页的注册入口同时收起，改为提示找管理员。这是服务端强制，不是只藏按钮——
  绕过界面直接调接口同样被拒。首启空表时允许匿名建第一个账户（否则没人能开第一个号），
  想恢复自助注册可在 `flowtask_config.json` 里设 `"openRegistration": true`。
- **初始口令随机生成 + 首登改密**：管理员建号或重置密码时会给出 10 位随机口令（排除易混的 0/O/1/l），
  可一键复制；对方用初始口令登录后会被引导改密（可关闭、不锁人），成员列表用「待改密」标显示谁还没换，
  本人改密后标记自动清除。管理员还可通过 `POST /api/resetpw`（仅管理员会话）重置他人密码，旧口令立刻失效。
- **改密与重置一律由服务端执行**：页面拿不到任何人 `salt`/密码哈希（脱敏），
  所以本地比对必然失败——v1.9 修掉了这条一直走不通的路，改为 challenge → 旧证明 → `/api/changepw`。
- 会话令牌格式 `uid.exp.签名`，签名是服务端 HMAC-SHA256（密钥存 `flowtask_secret.json`，
  不入库、不下发给前端），因此**服务重启后旧会话仍然有效**，被篡改或过期立即失效。
- **登录失败限速**（v1.10）：同一账户 + 来源 IP 连续失败 5 次起指数退避（封顶 60 秒），成功即清零。
  注意：口令证明本身仍是可重放的密码等价物（challenge 无一次性 nonce）——服务默认只监听
  `127.0.0.1`，若设 `FLOWTASK_HOST` 跨网段部署，请自行加 TLS/反向代理。
- 服务端按会话里的 uid 定位个人库文件，**前端无法指定别人的文件**（403）。
- 顶栏用户菜单可「退出登录」（原生按钮，纯键盘也可达）；换账户登录看到的是另一套完全隔离的数据。

## 数据模型（v1.5：三份物理文件）

| 文件 | 内容 | 版本号 |
|------|------|--------|
| `flowtask_auth.json` | 账户表：用户名、显示名、角色、PBKDF2 口令哈希 | 独立 `rev` |
| `flowtask_data_<账户id>.json` | 该账户的个人库：项目 / 任务 / 通知 / 回收站 / 标签 / 筛选视图 | 独立 `rev` |
| `flowtask_shared.json` | 团队共享库：被设为「共享」的项目及其任务与通知 | 独立 `rev` |

- 内存里是**单一合并视图**（个人库 ⊕ 共享库），保存时按 `project.scope` 自动拆回对应文件；
  项目连同其任务、通知、回收站条目一起迁移，所以"共享出去/收回来"是一次原子写盘。
- 只有**内容真的变了**的那个文件才会被写，账户表与任务数据也各自记账——
  改密码、改角色不会顶高任务数据的版本号。

## 数据安全模型

- **令牌鉴权**：服务启动时生成随机令牌，注入页面；写数据必须携带
  `X-FlowTask-Token`。令牌只发放给可信来源（同源页面 / file://）。
- **版本冲突保护（只在真冲突时提示）**：每个文件各自维护 `meta.rev`；服务端拒绝旧版本写入，但会先比内容哈希——**同版本 + 内容一致视为重复提交，幂等返回 200**，只有内容确实不同才返回 409。不同账户各写各的文件，因此正常使用不会再看到冲突弹窗。
  前端会先把你的改动留底成冲突副本文件、采用服务端较新版本，然后弹出对话框让你选：
  **先看最新数据 / 下载我的副本 / 保留我的改动**（后者会二次确认）。
  对话框会说明冲突发生在**哪个库**、双方版本号、差异处数与留底文件名；
  历史留底列在「数据管理 → 冲突副本」，可随时下载比对。
- **导入前自动留底**：导入备份会先把当前数据留底，再覆盖。
- **多标签页同步**：任一标签页保存后通过 BroadcastChannel 广播，其余页面自动拉新；
  页面回到前台时核对版本号。
- **自动备份**：写入前（间隔≥10 分钟）自动备份到 `backups/`，保留最近 40 份。
- **损坏自愈**：数据文件损坏时服务端自动隔离为 `flowtask_data_corrupt_<时间>.json` 并让前端重建。
- **本地写盘防抖**：连续改动合并为一次序列化；关页或切后台前强制落盘。
- **渲染索引**：按数据纪元失效，避免"每个项目都全表扫描一遍"。
- **密码**：PBKDF2-SHA256（10 万轮）存储，旧哈希登录后自动透明升级。

### 共享盘同步（可选，默认关闭）

本机数据永远是第一份拷贝；配好共享盘目录后，服务在后台把它镜像过去，
实现「换电脑登录同一账号就能拿回自己的资料」。**开启方式（优先级从高到低）**：

1. **界面里改**（推荐）：管理员进「数据管理 → 共享盘同步」，填路径保存即可，**立即生效不用重启**。
   会先做一次无副作用探测：路径打不开就直接说明并拒绝，不会凭空建目录、不会假装已同步；
   探测通过才弹确认框（换路径有真实后果：新位置可能有别人更新的数据）。
   「停用同步」只关开关，路径仍留在配置里，再启用不必重敲长路径。
   共享盘按部门/账户权限不同，每个人可以指到自己能读写的那份目录。
2. **配置文件**：把 `flowtask_config.example.json` 改名为 `flowtask_config.json` 放在**数据目录**
   （默认就是 FlowTask 文件夹）。填 `"syncEnabled": false` 可临时停用而保留路径。
   该文件含机器相关信息，已在 `.gitignore` 里，不会入库；拷文件夹到别的电脑时记得单独放一份。
3. 环境变量 `FLOWTASK_SHARE_DIR`，或 PowerShell 版的 `-ShareDir` 参数（两者都覆盖配置文件，
   也因此会让界面里的修改在重启后被顶回——面板会明确提示这一点）。
4. 什么都不配 = 纯本机模式，界面与行为与旧版完全一致（顶栏连那枚同步按钮都不出现）。

> 路径必须是**已经存在且你写得进**的目录（先在资源管理器里能打开）。程序不会替你创建它——
> 路径打错时若自动建目录，数据会静默落进一个谁都不知道的地方，而界面还显示「已同步」。
> 校验不过时顶栏会显示「⚠ 共享盘打不开」并在提示里给出具体原因，本机数据照常保存。

配置好之后顶栏会出现一枚状态签：`☁ 已同步 14:03` / `⏳ 同步中…` / `⚠ 共享盘断开` / `⚠ 共享盘打不开`。

**同步是自动的，不需要点。** 你保存（`Ctrl+S` 那条链路、加任务、改状态……）→ 本机先落盘 → 服务端随后把它
镜像到共享盘（Node 版约 3 秒去抖，PowerShell 版回包后即推）。顶栏那枚签子会在保存后自动转「同步中」、
镜像完成就回到「已同步」；**点击只是"立刻催一次"**，不是同步的前提。页面每 30 秒还会核对一次，
别的电脑推上来的更新会自动采纳。

共享盘目录长这样：

```
\\server\share\FlowTask\
  team\flowtask_auth.json / flowtask_shared.json   账户表与团队共享库（写前抢锁）
  users\<uid>\flowtask_data_<uid>.json             每人一份，唯一写者就是本人
  locks\                                            跨机锁（独占创建 + 60s 超时抢占）
  conflict\                                         真冲突时本机与对方各留一份底
```

规则只有三条：版本号 `meta.rev` 高者胜；同版本不同内容算真冲突，**双方都先留底再定胜负**；
共享盘「读不到」时，只有明确的不存在（`ENOENT`）才当作没有，网络断开/无权限一律不动、绝不覆盖。
完全不开启时，服务端行为与没有这套机制时完全一致。架构与分期：本地库 + 后台同步引擎 + 三路合并内核，分三期落地。

### 多人同时改同一份数据会怎样（v1.9 起：实体级三路合并）

共享盘上不跑任何代码，没有"服务器"能裁定谁的改动算数，所以合并发生在**每台机器自己的本地服务**里：
每台机器在数据目录留一份「共同祖先」快照（`<库名>.base.json`，绝不上共享盘），推送前比较
`base / 我的 / 盘上的` 三份：

- 只有一边改过 → 直接推或拉；
- 两边都改过 → 按实体 id 合并（任务、项目、通知、标签、成员、账户各算一条），
  再对同一条实体**逐字段**合并：你和同事各建各的任务 → 两条都在；他改标题、你改负责人 → 两处改动都保留；
  同一任务下各加一条评论 → 两条都留；
- 只有「同一条实体的同一个字段被改成不同值」才算真冲突，此时按与主客无关的确定性规则裁决
  （所属实体时间戳优先，再比规范化字符串），并把 base/我的/对方的/合并结果一起留底到
  `conflict\<库名>_merge_<时间>.json` 供人工比对。

裁决规则刻意做成对称的：同一份三份数据在任何一台机器上算出的结果都相同，
否则两台机器会各自收敛到不同状态，合并本身反倒成了新冲突源。
本功能是渐进生效的——没有基线时沿用旧的版本号规则并顺手落下基线，**不需要迁移任何历史数据**。

同步也不会因为"同事正好在推"而被放弃：拿不到锁时按 1.5/4/9/20 秒退避重试；
两端都会定期从共享盘拉取（否则长开的机器永远看不到同事的改动）。

部署到新环境后，用冒烟工具验证这台机器到共享盘的链路真的通：

```
node smoke_share.js "\\\\文件服务器\\共享\\FlowTask"      # 或先设 FLOWTASK_SHARE_DIR 再直接运行
```

它自建一个临时本机数据目录，把「建账户 → 登录 → 保存 → 共享盘出现镜像 → 跨机锁挡住写入 →
锁超时抢占 → 同版本冲突双方留底」整条链路在真实 SMB 上跑一遍并打印实际延迟（本机保存到共享盘可见
约 3 秒，含 3 秒去抖），跑完只清理自己登记过、且开跑前不存在的路径——目录非空就不删，
共享盘上原有数据一律不碰。目标目录非空时需要显式加 `--allow-nonempty` 才肯运行。

数据管理页（管理员）支持导出/导入 JSON 备份；导入有结构校验，失败时提示用户语言的原因。
