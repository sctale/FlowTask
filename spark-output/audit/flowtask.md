## 改版机会点（按优先级排序）

### 🥇 高优先级

**机会点 1：把"数据到底存住了没有"变成看得见的承诺**

- 关联 findings（8 条）：audit-12, audit-13, audit-1, audit-2, audit-9, audit-10, audit-30, audit-47
- 影响范围：顶栏存储胶囊、409 冲突处理、所有弹窗关闭路径、导入导出、回收站/撤销、登录页文案
- 优先级理由：含 2 个 blocker（冲突静默覆盖本地改动、弹窗输入即关即丢）。这个产品的卖点是"数据在你自己机器上"，但保存中/已保存/仅缓存三态无法区分，冲突副本在 UI 里找不回来，登录页还谎报存储位置——用户一旦怀疑数据安全性，就不会把团队数据放进来。修完这一组，"敢给同事用"才成立。

**机会点 2：一份术语表 + 一套状态色板，把语言不一致一次清干净**

- 关联 findings（12 条）：audit-6, audit-7, audit-8, audit-11, audit-18, audit-19, audit-20, audit-21, audit-22, audit-23, audit-24, audit-25
- 影响范围：全站文案 + STATUS_PILLS/status-pill/status-chip 三处配色 + 按钮 okText 约定 + :root token 层
- 优先级理由：12 个 finding 里最"便宜"的一批：优先级四叫法、状态三套配色、"永久删除"文案与行为相反、三个新建入口三种叫法、按钮动词不统一、token 定义了不用。这些不需要重设计，只需要一次 sweep + 一份写进 README 的词汇/色板规范，之后靠 lint 守住。收益是"看起来像成品"而不是原型。

**机会点 3：表单防错与提交反馈统一化**

- 关联 findings（8 条）：audit-26, audit-27, audit-28, audit-29, audit-31, audit-14, audit-15, audit-16
- 影响范围：openModal/openPromptModal、快速添加、新建项目、抽屉日期字段、批量条、筛选面板
- 优先级理由：日期倒挂不校验、校验只在提交瞬间、错误呈现两套（toast 满屏飞 vs 登录页行内）、主按钮不防连点可双建、Esc 一次关掉所有层叠弹窗、切筛选静默清空多选。这些是"每天用就会撞上"的问题，直接决定误操作率；且集中在 openModal/openPromptModal 两个函数里，一次改造全站受益。

**机会点 4：渲染与写入性能：让勾选不卡**

- 关联 findings（4 条）：audit-53, audit-54, audit-5, audit-41
- 影响范围：renderApp/saveDB、列表视图、看板视图、甘特、首页统计、全局搜索
- 优先级理由：每次点勾选都全量 stringify 写盘 + 整页 innerHTML 重建，无虚拟化、无分页。团队用起来数据量只会涨，这是唯一一条"越用越差"的退化型问题，优先级要高于视觉优化。骨架屏和搜索截断顺带一起做。

### 🥈 中优先级

**机会点 5：三态补齐 + 最小帮助层：空态/筛选空/错误态 + 快捷键面板**

- 关联 findings（8 条）：audit-3, audit-4, audit-45, audit-46, audit-48, audit-49, audit-32, audit-34

- 优先级理由：看板空列在筛选生效时还说"拖拽卡片到此列"、导入失败抛英文 SyntaxError、拖放失败静默、全站零引导零帮助入口、快捷键只活在 README 里。这类问题的特征是"用户不会报错，只会少用一个功能"。一个 ? 面板 + 一套三态模板就能覆盖，成本可控。

**机会点 6：首页与列表行的信息层级重排**

- 关联 findings（5 条）：audit-41, audit-42, audit-43, audit-44, audit-33
- 影响范围：renderHome 四卡 + 统计条、taskRowHTML、boardCardHTML、抽屉协作者行、图标层

**机会点 7：效率层：快速添加自然语言解析 + 保存筛选 + 复制链接 + 任务复制**

- 关联 findings（6 条）：audit-37, audit-36, audit-35, audit-38, audit-39, audit-40

- 关联 findings（4 条）：audit-50, audit-51, audit-52, audit-17

- 优先级理由：audit-50 按框架是 blocker（全文件仅 1 个非断点 @media，390px 下看板/甘特横向溢出），但本产品定位是本机桌面工具，触屏频次低，故整体排中优先级；其中键盘可达性更实际——task-row/view-tab 都是无 tabindex 的 div，全文 0 个 aria-/role/tabindex，纯键盘无法完成"打开任务→改状态"。建议先补键盘与触控热区，再做两个断点。

## 完整 Findings 清单

### 维度 1. visibility — 系统状态可见性（Nielsen #1）

1. 🟠 **保存过程完全没有正向反馈，用户无法区分"已写入文件"和"只存在浏览器里"** · `audit-1`
   - 证据：L1173-1182 每次变更同步写 localStorage、400ms 防抖推送服务端，仅失败时调用 svcMarkDown()；顶栏存储胶囊 L755/1185-1203 只显示"💾 文件存储 / ⚠ 浏览器存储"两态，没有"保存中/已保存/上次保存时间"
   - 修复建议：存储胶囊升级为四态：保存中… / ✓ 已保存到文件（含 HH:MM:SS 时间戳）/ ⚠ 仅浏览器缓存 / ✕ 保存失败·点击重试；勾选完成等高频操作补一个 300ms 的微反馈（胶囊闪一下）
   - 修复成本：medium（1-2 天）

2. 🟠 **全站没有任何 loading 态；启动探测存储服务最长 1.5 秒期间，已登录用户会先看到登录表单** · `audit-2`
   - 证据：L142 #auth-page 默认 display:flex 可见；L1017 setTimeout(()=>ctrl.abort(),1500)；grep loading|spinner|skeleton 只命中任务完成度 .progress-bar；导入导出 L3582-3604 全程静默（大 JSON 数秒无反馈）
   - 修复建议：启动期给"正在连接本地数据…"骨架而不是登录页；导入/导出/迁移按钮进入 pending 态并禁用；探测超时压缩到 400ms 后先渲染再补状态
   - 修复成本：quick-win（半天内）

3. 🟠 **筛选后的"空"和真正的"空项目"不区分，看板空列还固定说"拖拽卡片到此列"，把用户往错误方向指** · `audit-3`
   - 证据：L2341 board-col-empty 固定文案「拖拽卡片到此列」；L2158/2333 applyFilter 结果数被统计但没有任何"筛选无匹配 · 清除筛选"提示；日历/甘特同理
   - 修复建议：空态分三种文案：无任务（引导新建）/ 筛选后无结果（显示当前筛选条件 + 一键清除）/ 无权限（说明可见范围）；看板空列在 FILTER 生效时改为「当前筛选下没有卡片」
   - 修复成本：quick-win（半天内）

4. 🟡 **列表视图的空分组只剩"待办 0"标题和一片空白，访客在只读空项目里看到的是近乎白屏** · `audit-4`
   - 证据：L2168 ${items.map(t=>taskRowHTML(t)).join("")} 为空时输出空串，无占位；L2169 添加行被 canWrite 门控，访客连"＋ 添加任务"都没有
   - 修复建议：空分组渲染一行浅色占位（「此状态还没有任务」/ 访客态「该项目暂无此状态任务」），保持行高一致避免布局跳动
   - 修复成本：quick-win（半天内）

5. 🟡 **搜索结果被静默截断，用户以为"没有更多了"** · `audit-5`
   - 证据：L3982 项目 .slice(0,4)、L3989 任务 .slice(0,8)，超出部分无任何提示；L3991 无匹配时只有一行不可点击的「无匹配结果」
   - 修复建议：截断时末尾补「还有 N 条结果 · 回车查看全部」，点击跳到列表视图并自动把关键词写入筛选；无匹配时给"清除搜索"动作
   - 修复成本：quick-win（半天内）

### 维度 2. real-world-match — 系统与现实世界匹配（Nielsen #2）

1. 🟠 **同一个优先级概念有四种叫法，用户在筛选面板里找不到抽屉里那个"中"** · `audit-6`
   - 证据：L936 PRIO={high:"高",med:"中",low:"低"}；L2811 抽屉显示「中」；L2029 筛选面板写「中优先」；L1997 已选筛选 chip 拼成「中优先」；L2579 甘特图例写「高优先级」
   - 修复建议：定一处词汇表：优先级 = 高/中/低（图例可写"高优先级"但同一屏内不混用），所有 chip/图例/提示从 prioName() 派生，禁止字符串拼接"优先"
   - 修复成本：quick-win（半天内）

2. 🟠 **标签和优先级用同一套彩色实心 pill 渲染，"紧急"标签看起来就像高优先级** · `audit-7`
   - 证据：L1242 演示标签「紧急」color:#dc2626（红）；L2424 prio-pill 也是红色实心 pill；列表行 L1782-1793 两者并排出现，形状权重相同
   - 修复建议：优先级改用"文字 + 左侧色条/色点"的固定形态，标签统一改用描边浅色 pill（颜色只用于分类不用于强调），确保任何标签名都不会伪装成优先级
   - 修复成本：medium（1-2 天）

3. 🟠 **"负责人"一个词指两件事（项目负责人 / 任务负责人），动作又叫"指派"，筛选里叫"未指派"** · `audit-8`
   - 证据：L2655/2663「项目负责人」= proj.ownerId；L2792/3202「负责人」= assigneeId；L2259 批量条「👤 指派…」；L1441 通知「指派给了你」；L2026 筛选项「未指派」
   - 修复建议：拆词：proj.ownerId →「创建人/项目拥有者」，task.assigneeId →「负责人」，动作统一「指派给…」，空态统一「未指派」；写入词汇表并在 code review 里当硬约束
   - 修复成本：quick-win（半天内）

4. 🟠 **登录页长期谎报数据存放位置，与侧栏自己的说明互相矛盾** · `audit-9`
   - 证据：L4061 auth-sub 固定文案「本地团队项目管理 · 数据完全存储于本机浏览器」；而 L1570 侧栏脚注在文件服务模式显示「💾 数据保存到 flowtask_data.json」
   - 修复建议：auth-sub 按 SVC_MODE 动态取词：文件服务在跑时写「数据保存在本机文件 flowtask_data.json」，未跑时写「数据暂存浏览器缓存，启动服务后可迁移上文件」
   - 修复成本：quick-win（半天内）

5. 🟡 **内部实现词汇直接漏到用户界面** · `audit-10`
   - 证据：L1074「你的副本已保存为 conflict 文件」；L4124 显示损坏文件名；L3604 直吐 L3533「缺少必备字段或类型不符：users 应为数组」、L3539「存在缺少 id 的条目」；侧栏脚注出现 localStorage（截图 01_home.png 可见）
   - 修复建议：建一层"用户语言"文案表：conflict 文件→「你的改动副本」、数组/id→「备份文件结构不完整，第 N 条记录缺少编号」；技术细节收进"查看详情"折叠区
   - 修复成本：quick-win（半天内）

6. 🟡 **"协作者"字段其实是"关注任务动态"，与项目成员概念叠床架屋** · `audit-11`
   - 证据：L1276 字段名 followers；L2818 UI 标签「协作者」；L2750 tooltip「关注任务动态」；同时项目层还有 memberIds「项目成员」（L2659）
   - 修复建议：二选一：要么统一叫「关注人」并说明"只接收动态、不获得编辑权"，要么并入协作者并明确权限差异；tooltip 与标签必须同源
   - 修复成本：quick-win（半天内）

### 维度 3. user-control — 用户控制与自由（Nielsen #3）

1. 🔴 **版本冲突时用户的本地改动被静默覆盖，副本在界面里没有任何找回入口** · `audit-12`
   - 证据：L1051 409 → resolveSvcConflict()；L1063-1073 直接 DB = remote 并 renderApp()，只在 L1074 toast 一句「已采用最新版本，你的副本已保存为 conflict 文件」；UI 无"查看/对比/合并我的副本"入口，文件路径也不告知
   - 修复建议：冲突改为可决策弹层：并排显示"服务端版本 vs 你的版本"差异条数 + 三个动作（用我的 / 用最新的 / 先导出我的副本再刷新），并给出副本文件的可点击路径；至少要在回收站旁加一个"冲突副本"列表
   - 修复成本：major-rework（3 天+）

2. 🔴 **弹窗里已输入的内容，按 Esc 或点遮罩就无声消失，没有任何挽留** · `audit-13`
   - 证据：L3687 点遮罩直接 close()；L3854 Esc → maskRemoveAll()；两条路径都不检查输入是否非空、也不弹二次确认；快速添加里写 30 字标题后误触 = 内容归零
   - 修复建议：close/onCancel 前统一走 guardUnsaved()：任一字段非空则确认「放弃已输入的内容？」；快速添加可改为自动存草稿，下次打开回填
   - 修复成本：medium（1-2 天）

3. 🟠 **Esc 一次关掉所有层叠弹窗，与 README 宣称的"逐层关闭"不符** · `audit-14`
   - 证据：L3854 if($(".modal-mask")) maskRemoveAll() —— 抽屉里新建标签（prompt 叠在 modal 上）时按 Esc 会连外层一起关掉；README 快捷键表写的是「Esc 逐层关闭 弹层 → 弹窗 → 抽屉」
   - 修复建议：maskRemoveAll 改为只移除栈顶一层（维护 modalStack，Esc pop 一个），行为与文档对齐
   - 修复成本：quick-win（半天内）

4. 🟠 **切换筛选条件会静默清空已勾选的多选，批量操作做到一半丢选择** · `audit-15`
   - 证据：L2135 筛选 chip 点击处理里 MULTI.on=false; MULTI.ids.clear()，无提示；多选集合本身能跨重渲染保留（L2187 按 MULTI.ids 重新着色），唯独筛选这条路径丢
   - 修复建议：筛选变化时保留仍然匹配的已选项，被过滤掉的项在批量条上标注「N 项已被当前筛选隐藏（仍会处理）」，并提供"仅处理可见项"
   - 修复成本：medium（1-2 天）

5. 🟡 **批量"标记完成/取消完成/指派/改期"没有任何反馈与撤销，只有批量删除有** · `audit-16`

### 维度 12. performance — 性能感知（自定义）

1. 🟠 **任何一次改动都全量重建 DOM + 全量序列化写盘，几百条任务后开始明显掉帧** · `audit-53`

   - 修复成本：quick-win（半天内）

## 走查中确认"已经做得好"的部分（避免误改）

- 破坏性操作基本都有 confirm + 回收站 + 6 秒撤销三段式，且确认文案里写清了后果（未完成任务数、连带删除评论与活动）——这是很多上线产品都做不到的水准。
- 同一 route 下的滚动位置在每次重渲染后被恢复（L1485/1491），抽屉保留自己的滚动（L2723），改一个勾选不会跳回顶部。
- 权限模型在 UI 内有解释（L3451-3455），只读态有横幅（L2088）与逐字段降级渲染（L2789-2816），访客不会看到一堆点了没反应的按钮。
- 快捷键全部经 typing 门禁（L3850/3858），在输入框里敲 n / / 不会误触发。
- 拖拽反馈三件套齐全：拖起半透明 + 落点品牌色指示线 + 目标列变底色（L293-298 / L357-362 / L2384），优于多数同类实现。
- 存储模式是"活的"可点击指示器，带自动重连与恢复提示（L1104/1126/1185-1204），文案直说"双击启动存储服务.bat"，可行动。
- 回收站孤儿恢复有兜底：所属项目也在回收站时给出标注与提示（L1946-1948 / L3624 / L3657）。
- 安全侧零外部资源：CSP default-src none、零外链零图片零 base64、系统字体栈、通知渲染统一转义、导入做结构与 id 唯一性校验——首屏不会被网络阻塞，也没有 XSS 面。
- 筛选激活后状态可见：chip 化 + 单项可移除 + 一键清除全部（L1999-2013）。
